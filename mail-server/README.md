# Корпоративная почта на своём сервере (Mailcow)

Инструкция и скрипты для своего почтового сервера на ~1000 сотрудников:
у каждого один ящик с IMAP и три алиаса для трёх аккаунтов в рабочем сервисе.

```
ivan.petrov@company.ru      ← ящик (IMAP, пароль)
ivan.petrov.1@company.ru  ┐
ivan.petrov.2@company.ru  ├─ алиасы → всё приходит в ivan.petrov@
ivan.petrov.3@company.ru  ┘
```

| Файл | Что делает |
|---|---|
| `provision_mail.py` | Создаёт ящики и алиасы по CSV со списком сотрудников (через API Mailcow) |
| `fetch_confirmations.py` | По IMAP собирает письма подтверждения от сервиса: ссылки и коды, с привязкой к алиасу |
| `employees.example.csv` | Пример входного файла |

---

## Этап 0. Сделать сразу (не откладывать)

1. **Купить домен**, например `company.ru` (REG.RU, RU-CENTER, Cloudflare).
   Возраст домена влияет на доверие, поэтому каждая неделя до старта работает на вас.
2. **Сделать простой сайт** на этом домене: о компании, контакты, реквизиты (Tilda или любой конструктор).
3. **Написать в поддержку сервиса**: компания на ~1000 сотрудников подключает каждому
   по 3 аккаунта в рамках разрешённого лимита в 5, с корпоративного домена `company.ru`.
   Спросить про бизнес-подключение, рекомендуемый темп и возможность добавить домен в доверенные.

## Этап 1. Сервер

**Требования к VPS**
- 2 vCPU, 4–6 ГБ RAM (без ClamAV хватит 4 ГБ, с ClamAV лучше 6+), 60+ ГБ SSD.
  Почтовые вложения растут, закладывайте место с запасом.
- Ubuntu 22.04/24.04 или Debian 12.
- **Статический IP, открытый исходящий порт 25 и возможность задать PTR.** Без этого почта работать не будет.
  Подходят Hetzner, OVH, Vultr, Linode, Selectel, Timeweb Cloud.
  У многих хостеров порт 25 открывают по заявке в поддержку, это нормально.
- Перед тем как пользоваться IP, проверьте, что он не в чёрных списках:
  https://mxtoolbox.com/blacklists.aspx. Если адрес «грязный», попросите у хостера другой.

**Установка Mailcow** (официальная документация: https://docs.mailcow.email)

```bash
apt update && apt install -y git curl
curl -sSL https://get.docker.com | sh

cd /opt
git clone https://github.com/mailcow/mailcow-dockerized
cd mailcow-dockerized
./generate_config.sh          # спросит FQDN: mail.company.ru
docker compose pull
docker compose up -d
```

Веб-интерфейс откроется на `https://mail.company.ru`, логин `admin` / пароль `moohoo`.
**Пароль смените сразу** и включите для admin двухфакторную аутентификацию.

Сертификат Let's Encrypt Mailcow получит сам, как только DNS-записи из этапа 2 начнут работать.

## Этап 2. DNS (самое важное для репутации)

Замените `company.ru` и `203.0.113.10` на свои значения.

| Тип | Имя | Значение |
|---|---|---|
| A | `mail` | `203.0.113.10` |
| MX | `@` | `mail.company.ru` (приоритет 10) |
| TXT | `@` | `v=spf1 mx -all` |
| TXT | `dkim._domainkey` | ключ из Mailcow: *Configuration → ARC/DKIM keys* (2048 бит) |
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:dmarc@company.ru` |
| CNAME | `autodiscover` | `mail.company.ru` |
| CNAME | `autoconfig` | `mail.company.ru` |
| **PTR** | IP сервера | `mail.company.ru` (**задаётся в панели хостера**, а не у регистратора домена) |

Через месяц стабильной работы DMARC можно ужесточить до `p=reject`.

**Проверка**
- https://www.mail-tester.com: отправьте туда письмо из любого ящика, нужно получить **10/10**.
- В Mailcow: *Configuration → Mail setup → DNS* показывает, какие записи не настроены.
- `dig +short -x 203.0.113.10` должен вернуть `mail.company.ru.`

## Этап 3. Домен и API в Mailcow

1. *Configuration → Mail setup → Domains → Add domain*: `company.ru`.
   - Max. mailboxes: 1100 и больше, Max. aliases: 3500 и больше, общая квота: с запасом
     (например, 1100 ГБ при квоте ящика 1 ГБ).
2. *System → Configuration → Access → Edit administrator details → API*:
   - включите **Read-Write API**;
   - в *Allow API access from these IPs* укажите только IP машины, с которой запускаются скрипты;
   - скопируйте ключ API.

## Этап 4. Создание ящиков

```bash
cd mail-server
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# employees.csv: колонки first_name,last_name[,login][,department]
cp employees.example.csv employees.csv   # и заполните

# 1) Проверка без изменений: какие адреса получатся
python3 provision_mail.py employees.csv --domain company.ru --dry-run

# 2) Создание
export MAILCOW_URL=https://mail.company.ru
export MAILCOW_API_KEY=ваш_ключ
python3 provision_mail.py employees.csv --domain company.ru
```

- Логины генерируются транслитом: `Иван Петров` → `ivan.petrov`. При совпадении ФИО
  получается `ivan.petrov2`. Чтобы задать логин вручную, заполните колонку `login`.
- Скрипт можно запускать повторно: существующие ящики и алиасы пропускаются.
  Новых сотрудников **добавляйте в конец CSV**: номер при совпадении ФИО (`ivan.petrov2`)
  зависит от порядка строк, поэтому старые строки не переставляйте и не удаляйте.
- Пароли **новых** ящиков пишутся в `credentials.csv` с правами 600.
  Это секрет: раздайте пароли, перенесите их в менеджер паролей, а файл удалите
  (или храните в зашифрованном виде). Файл в `.gitignore`, в git он не попадёт.
- Суффиксы алиасов меняются параметром `--alias-suffixes 1,2,3`
  (например, `--alias-suffixes main,work,test`). Адреса с `+` не используйте:
  многие сервисы их не принимают.

## Этап 5. Подключение сотрудников к сервису

**Темп.** Если сервис сам не назвал скорость, двигайтесь волнами:

| Неделя | Кого подключаем |
|---|---|
| 1 | пилот: 20–50 человек, проверяем, что всё проходит без капч и отказов |
| 2–6 | по 100–200 человек в неделю, по отделам |

При первых признаках проблем (капчи, отказы, блокировки) остановитесь и свяжитесь с поддержкой сервиса.

**Лучше всего, когда каждый регистрирует свои аккаунты сам**, со своего устройства, по инструкции
(шаблон ниже). Аккаунты персональные, так что это честно и выглядит ровно так, как есть на самом деле.
Регистрировать тысячи аккаунтов скриптом с одного компьютера и IP не стоит:
антифрод почти наверняка примет это за бот-ферму, даже если лимит не нарушен.

**Сбор писем подтверждения** (если сотруднику неудобно заходить в почту, или чтобы проверить, кто
уже подтвердил регистрацию):

```bash
python3 fetch_confirmations.py --host mail.company.ru \
    --from noreply@service.example \
    --link-regex 'https://service\.example/[^\s"<>]+' \
    --since-days 2
# или для кодов:
#   --link-regex '' --code-regex '\b\d{6}\b'
```

Результат появится в `confirmations.csv`, в колонке `alias` видно, к какому из трёх аккаунтов относится письмо.

*Мастер-пользователь* позволяет читать ящики без паролей сотрудников. В `mailcow.conf` задайте
`DOVECOT_MASTER_USER` и `DOVECOT_MASTER_PASS`, затем выполните `docker compose up -d`
(уточните в документации Mailcow для своей версии). Запуск: `--master-user ИМЯ`, пароль в `IMAP_MASTER_PASS`.
Доступ ко всем ящикам компании — чувствительная вещь: используйте его только для служебных задач
и предупредите сотрудников.

### Шаблон письма сотруднику

> **Тема:** Ваша рабочая почта и подключение к <Сервис>
>
> Здравствуйте, {Имя}!
>
> Ваша рабочая почта: **{email}**, пароль: выдаётся лично / в менеджере паролей.
> Веб-почта: https://mail.company.ru · Почта на телефоне: IMAP `mail.company.ru`, порт 993, SSL.
>
> Для работы зарегистрируйте в <Сервис> три аккаунта на адреса:
> 1. {email_1}: <для чего>
> 2. {email_2}: <для чего>
> 3. {email_3}: <для чего>
>
> Все письма на эти адреса приходят в ваш основной ящик.
> Сделайте это до {дата}. Если что-то не получилось, пишите на it@company.ru.

## Эксплуатация (обязательно)

- **Бэкапы:** `/opt/mailcow-dockerized/helper-scripts/backup_and_restore.sh backup all`
  по cron каждую ночь, копию храните **на другом сервере** или в объектном хранилище.
- **Обновления:** раз в 1–2 недели `./update.sh` в папке Mailcow.
- **Мониторинг:** Google Postmaster Tools, отчёты DMARC (`rua`), периодическая проверка IP в блок-листах.
- **Безопасность:** надёжные пароли (скрипт генерирует 16 символов), 2FA для админов,
  API доступен только с разрешённых IP. Неиспользуемые ящики уволенных сотрудников отключайте.
- Если внутри нет человека, который будет за этим следить, отдайте обслуживание подрядчику:
  взломанный почтовый сервер быстро попадает в спам-листы, и тогда страдает вся компания.
